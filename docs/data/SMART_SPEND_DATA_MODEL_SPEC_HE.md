# 1. סקירה כללית (Overview)

## 1.1 מטרה

מפרט מודל הנתונים של SmartSpend מגדיר את הישויות המרכזיות במערכת, את השדות שלהן ואת הקשרים ביניהן.

מסמך זה משמש כמקור משותף עבור:

* תכנון Database
* הגדרת API
* מימוש Frontend
* מימוש לוגיקה עסקית

## 1.2 תחום אחריות

מודל הנתונים תומך ביכולות הבאות:

* ניהול הטבות אישיות
* מעקב אחר תאריכי תפוגה
* ניהול קשרים בין ספקים ובתי עסק
* סיווג הטבות לפי קטגוריות
* יצירת מידע עבור מסך הבית

גרסת ה־MVP מיועדת למשתמשת יחידה תוך שמירה על יכולת הרחבה עתידית.

# 2. עקרונות מידול נתונים

מודל הנתונים מבוסס על העקרונות הבאים:

* הפרדה ברורה בין ישויות

# 3. סקירת ישויות

הישויות המרכזיות במערכת:

| ישות             | תיאור                              |
| ---------------- | ---------------------------------- |
| Benefit          | הטבה, תו קנייה, קופון או שובר אישי |
| Provider         | ארגון או חברה המנפיקים הטבה        |
| Store            | בית עסק שבו ניתן לממש הטבה         |
| Category         | סיווג של הטבות                     |
| DashboardSummary | מידע מחושב עבור מסך הבית           |

# 4. הגדרת ישויות

# 4.1 Benefit (הטבה)

## תיאור

מייצגת הטבה אישית השמורה במערכת.

דוגמאות:

* תו קנייה
* קופון הנחה
* שובר
* הטבת עובד

## שדות

| שדה            | סוג      | חובה | תיאור                 |
| -------------- | -------- | ---- | --------------------- |
| id             | UUID     | כן   | מזהה ייחודי של ההטבה  |
| name           | String   | כן   | שם ההטבה להצגה        |
| providerId     | UUID     | לא   | מזהה הספק הקשור       |
| categoryId     | UUID     | לא   | מזהה הקטגוריה הקשורה  |
| value          | Number   | לא   | ערך כספי או ערך ההטבה |
| currency       | String   | לא   | קוד מטבע              |
| expirationDate | Date     | לא   | תאריך תפוגה           |
| status         | Enum     | כן   | סטטוס נוכחי של ההטבה  |
| notes          | String   | לא   | הערות משתמשת          |
| imageUrl       | String   | לא   | קישור לתמונה          |
| createdAt      | DateTime | כן   | תאריך יצירה           |
| updatedAt      | DateTime | כן   | תאריך עדכון אחרון     |

## ערכי Status אפשריים

* ACTIVE
* EXPIRED
* USED
* ARCHIVED

---

## תיאור

מייצג את הגוף או החברה שהנפיקו את ההטבה.

דוגמאות:

* מקום עבודה
* חברת אשראי
* רשת חנויות
* ספק שירות

## שדות

| שדה        | סוג      | חובה | תיאור               |
| ---------- | -------- | ---- | ------------------- |
| id         | UUID     | כן   | מזהה ייחודי של הספק |
| name       | String   | כן   | שם הספק             |
| logoUrl    | String   | לא   | לוגו הספק           |
| websiteUrl | String   | לא   | אתר הספק            |
| notes      | String   | לא   | מידע נוסף           |
| createdAt  | DateTime | כן   | תאריך יצירה         |
| updatedAt  | DateTime | כן   | תאריך עדכון אחרון   |

---

# 4.5 DashboardSummary (סיכום מסך בית)

## תיאור

מייצג מידע מחושב המוצג במסך הבית.

ישות זו מחושבת בזמן אמת ואינה בהכרח נשמרת באופן קבוע.

## שדות

| שדה              | סוג     | חובה | תיאור                         |
| ---------------- | ------- | ---- | ----------------------------- |
| totalBenefits    | Integer | כן   | מספר כולל של הטבות            |
| activeBenefits   | Integer | כן   | מספר הטבות פעילות             |
| expiringBenefits | Integer | כן   | מספר הטבות שעומדות לפוג בקרוב |
| recentlyAdded    | List    | לא   | הטבות שנוספו לאחרונה          |

# 5. קשרים בין ישויות

## Benefit - Provider

קשר:

```text
Provider 1 ---- N Benefit
```

ספק אחד יכול להנפיק מספר הטבות.

הטבה יכולה להיות משויכת לספק אחד (באופן אופציונלי).

---

## Benefit - Category

קשר:

```text
Category 1 ---- N Benefit
```

קטגוריה אחת יכולה להכיל מספר הטבות.

הטבה יכולה להשתייך לקטגוריה אחת (באופן אופציונלי).

---

## Provider - Store

קשר:

```text
Provider 1 ---- N Store
```

ספק אחד יכול להיות קשור למספר בתי עסק.

---

## Benefit - Store

הרחבה עתידית:

```text
Benefit N ---- N Store
```

הטבה יכולה להיות ניתנת למימוש במספר בתי עסק.

קשר זה ימומש כאשר תידרש לוגיקת מימוש מרובת בתי עסק.
