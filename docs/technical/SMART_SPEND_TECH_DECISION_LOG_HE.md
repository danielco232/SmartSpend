# 1. סקירה כללית (Overview)

## 1.1 מטרה

מסמך זה מתעד את ההחלטות הטכנולוגיות המרכזיות שהתקבלו במהלך פיתוח פרויקט SmartSpend.

מטרת המסמך היא לשמור על שקיפות, עקביות ותיעוד של בחירות ארכיטקטוניות וטכנולוגיות לאורך חיי הפרויקט.

---

# 2. עקרונות קבלת החלטות

החלטות טכנולוגיות מתקבלות בהתאם לעקרונות הבאים:

* פשטות עבור פיתוח MVP
* יכולת הרחבה עתידית
* עלות תפעול נמוכה
* תחזוקתיות גבוהה
* הפרדה ברורה בין רכיבי המערכת
* פיתוח יעיל בסיוע כלי AI

---

# 3. החלטות טכנולוגיות

# החלטה 1 — פלטפורמת יעד

## החלטה

גרסת ה־MVP תפותח כאפליקציית Android-first.

## סיבות

* המשתמשת הראשונית היא משתמשת Android יחידה.
* מיקוד הפיתוח נשאר מצומצם בשלב ה־MVP.
* Flutter מאפשר הרחבה עתידית לפלטפורמות נוספות במידת הצורך.

---

# החלטה 2 — Framework לאפליקציה

## החלטה

האפליקציה תפותח באמצעות Flutter.

## סיבות

* בסיס קוד יחיד
* תמיכה חזקה בפיתוח Android
* אקוסיסטם רחב
* מתאים לפיתוח MVP מהיר
* מאפשר הרחבה עתידית לפלטפורמות נוספות

---

# החלטה 3 — Backend ו־Database

## החלטה

הפרויקט ישתמש ב־Supabase כפלטפורמת Backend וב־PostgreSQL כמנוע Database.

## סיבות

* מתאים למבנה מידע רלציוני
* תומך בקשרים בין ישויות
* מספק Database, API ויכולות Backend
* מאפשר פיתוח MVP באמצעות משאבי Free Tier
* מתאים למודל הנתונים של SmartSpend

---

# החלטה 4 — ניהול גרסאות

## החלטה

GitHub ישמש כפלטפורמת ניהול הגרסאות.

## סיבות

* שמירת היסטוריית שינויים
* תמיכה בשיתוף פעולה
* אינטגרציה עם כלי פיתוח

# החלטה 5 — כלי AI לסיוע בפיתוח

## סיבות

* סיוע בכתיבה ותחזוקת קוד
* מתאים לגישת פיתוח מבוססת תיעוד

# 4. החלטות טכנולוגיות עתידיות

הנושאים הבאים נדחים לשלב מאוחר יותר:

* Authentication מתקדם
* תהליך CI/CD
* Monitoring ו־Analytics
* אינטגרציות חיצוניות

נושאים אלו ייבחנו כאשר יהיה בהם צורך.
